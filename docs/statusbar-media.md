# Текущее воспроизведение в строке состояния OneOS

Переключатель «Текущее воспроизведение в строке состояния» на вкладке «Медиа» (по умолчанию
выключен) выводит в левую плашку строки состояния OEM SystemUI текст «Исполнитель — Трек»,
для радио — название станции или частоту. Плашка видна только во время воспроизведения; пауза,
остановка, отсутствие медиа и потеря связи с Media Bridge её закрывают.

## Подтверждено на головном устройстве

Geely OneOS G636, плагин `com.ecarx.systemui.plugin` 1.0.20250623G(312), проба из AtlasLauncher:

- штатная медиаплашка плагина не работает: `LeftTempStateViewModel.initMusicPlaying()` нигде не
  вызывается;
- плагин читает сервис «режим сцены» OneOS API (тип 13); штатного провайдера
  `com.geely.scene.mode` на G636 нет;
- `OneOSApiService.addService` принимает любой binder без проверки разрешений и рассылает
  клиентам `onServiceChanged`; плагин сам подключается и показывает плашку со значком сцены и
  названием сцены без префиксов;
- плашка видна при `open != 0` и `front == 0`; в открытом состоянии плагин не перечитывает
  название, поэтому смена текста — это `onOpenStateChanged(0)` и затем `onOpenStateChanged(1)`;
- нажатие на плашку уходит в отсутствующую активность `com.geely.scene.mode` и ничего не делает.

## Протокол (raw Binder, без AIDL)

- `IServiceManager` (`com.geely.service.oneosapi/.OneOSApiService`): 1 `addService(int, IBinder)`,
  2 `getService(int) → IBinder`.
- Наш `ISceneModeService`: 4 `getSceneModeOpenState`, 5 `getSceneModeFrontState` (всегда 0),
  6 `getSceneModeName`, 7/8 регистрация и снятие слушателя; 1–3 отвечают пустым успехом.
- `ISceneModeServiceChangedListener`: 1 `onOpenStateChanged(int)`; вызывается синхронно и не с
  главного потока.

Коды взяты из декомпилированной библиотеки oneosapi этой версии плагина и не являются стабильным
API.

## Реализация

- `StatusBarScene` — чистая логика: текст из снапшота и переходы открыть / переоткрыть / закрыть.
  Одинаковый текст ничего не отправляет.
- `OneOsStatusBarScene` — граница с OneOS: собственный поток для Binder-вызовов, подключение к
  OneOS API только после первого текста, повторная регистрация после перезапуска
  `OneOSApiService`, удаление слушателей, у которых транзакция не прошла.
- Источник — тот же снапшот Media Bridge, что рисует карточку, поэтому поддерживаются все его
  источники. Смена трека сглаживается паузой 500 мс, чтобы плашка не мигала дважды.
- Сервис живёт в `OverlayService` (foreground service) и работает, пока запущен оверлей или
  используется режим «Виджет». При остановке сервиса сцена закрывается.
- Если тип 13 уже занят живым binder другого приложения, он не заменяется. Мёртвый binder
  (например, от нашего прошлого процесса) заменяется.

## Ограничения и допущения

- OneOS API не следит за смертью нашего binder: если процесс убит с открытой сценой, плашка
  остаётся до перезагрузки головного устройства. Поэтому сервис регистрируется только из процесса
  с foreground service.
- При смене трека возможно короткое мигание плашки из-за переоткрытия сцены.
- Длинный текст обрезает сам плагин.
- Поведение после сна/пробуждения, перезапуска SystemUI и `OneOSApiService` и на других
  прошивках не подтверждено и требует проверки на головном устройстве.

# Android AppWidget и режим отображения

AtlasMediaWidget сохраняет `display_mode`: `overlay` по умолчанию, `widget` по выбору пользователя.
Обновление APK без этого ключа сохраняет прежний оверлей. Переходы не удаляют координаты,
размеры, параметры запуска, оформление, источники или избранное. Настройки общие для всех
экземпляров; профилей по appWidgetId нет. JSON-схема 12 добавляет размер миниатюры компактной
карточки; старые схемы получают прежние 76 dp. Схема 11 добавляет `widgetMode`; схемы 1–10
читаются с режимом Overlay. ZIP и журнал восстановления используют тот же набор параметров.

## Применимость настроек

| Настройка | Оверлей | Системный виджет |
| --- | --- | --- |
| Компактная / просторная компоновка карточки | Да | Да, общая для всех экземпляров; выбирается вручную, независимо от размера |
| Пять уровней затемнения обложки | Да | Да |
| Размер миниатюры обложки в компактной компоновке (48–104 dp) | Да | Да; общая настройка |
| Размеры текста источника, названия, исполнителя, времени | Да | Да |
| Верхний/боковой отступ, промежутки подзаголовка, метаданных и прогресса | Да | Да |
| Высота панели, масштаб/разбежка кнопок, нижний отступ | Да | Да; область нажатия основных кнопок не меньше 48 dp при достаточном размере HOME |
| Толщина линии прогресса | Да | Да; полоса только показывает положение |
| Размер и координаты окна, угол привязки, точки перемещения | Да | Скрыты; хранятся для возврата в оверлей |
| HOME-видимость, порог свободных окон | Да | Скрыты; размещением управляет HOME |
| Запуск/остановка оверлея, автозапуск оверлея | Да | Скрыты; сервис нужен, пока есть размещённые экземпляры |
| Переключение радио по сохранённым / избранным | Да | Да, через прежнюю маршрутизацию команд |
| Сетка избранных станций | В карточке | В карточке управления, открытой в MainActivity |
| Источник по умолчанию, Online-плеер, автопроигрывание, поведение потери источника | Да | Да, прежние настройки Media Bridge |
| Приборная панель, радио-каталог, обложки | Да | Да, прежние настройки медиабэкенда |
| «Поверх окон», Usage Access, оконная accessibility-служба | Нужны | Не требуются; кнопки скрыты |
| Notification Listener, USB-хранилище | По источнику | По источнику; не скрыты и не считаются разрешениями оверлея |
| Масштаб приложения | Окно настроек | Окно настроек; не масштабирует карточку на HOME |
| ZIP/JSON-настройки, отдельный радио-каталог | Да | Да |

Цвета, прозрачность фоновых слоёв и радиус карточки наследуются из MediaCardView. Отдельных
редакторов цвета/прозрачности/радиуса в AtlasMediaWidget нет; настройки AtlasAppWidget не
переносятся как новый независимый набор. Поддержанные параметры меняют RemoteViews всех
экземпляров. Ползунки применяются при отпускании, переключатели — сразу.

## Добавление, настройка и предпросмотр

Провайдер: `com.mmwtl.atlasmediawidget/.AtlasMediaWidgetProvider`.
Activity: `com.mmwtl.atlasmediawidget.MainActivity`, объявлена в `android:configure`.
Минимальный рекомендуемый размер — 280×200 dp, минимальный resize — 280×180 dp.

Кнопка «Добавить виджет» проверяет `isRequestPinAppWidgetSupported()` и отправляет запрос HOME.
Фактическое размещение и подтверждение принадлежат лаунчеру. Рядом всегда приведён ручной путь:
удержание свободной области HOME → Виджеты → AtlasMediaWidget. В AtlasLauncher также доступен
пункт «Редактировать рабочий стол» → «＋».

При `ACTION_APPWIDGET_CONFIGURE` проверяются ненулевой ID и принадлежность провайдеру.
По умолчанию Activity возвращает `RESULT_CANCELED` с исходным ID; «Готово» обновляет карточку
и возвращает `RESULT_OK` с тем же ID. Первичное добавление/отмена и удаление выделенного ID —
ответственность AppWidgetHost. Повторная настройка не выделяет и не удаляет ID. Общие параметры
применяются сразу: «Назад» не откатывает уже сохранённые изменения.

Предпросмотр применяет тот же RemoteViews, что настоящий AppWidget, включая тот же измеренный
MediaCardView и области кликов. Размер берётся из AppWidget options указанного ID, при запуске
через приложение — первого размещённого экземпляра. Без экземпляров показан «Пример размера
400×300 dp · демо». Предпросмотр показывает трек «Liminal Hours» и его обложку из
деморежима медиабэкенда; данные не являются текущим состоянием ГУ. В компактном режиме
обложка видна и на фоне с выбранным уровнем затемнения, и рядом с названием трека.
В компактной компоновке градиент сильнее затемняет верх и середину фоновой обложки;
миниатюра остаётся без затемнения.

На медиакарточке нет постоянной шестерёнки или полосы настроек. Неактивная карточка при режиме
«Оверлей» предлагает открыть выбор режима; она остаётся на HOME.

## Медиа, рендеринг и ограничения

OverlayService сохраняет прежний MediaBridgeClient, SnapshotReducer, transport reconciliation,
Online stabilizer, source/radio routing и загрузчик обложек. В widget-режиме сервис не прикрепляет
WindowManager-окно, не регистрирует события HOME и не опрашивает foreground-приложения.
Accessibility-служба, если пользователь ранее её разрешил, пропускает оконные наблюдения.

Provider обслуживает update, resize, restore и удаление, затем передаёт работу сервису. Он не
хранит постоянно живую подписку. Сервис переживает закрытие MainActivity (`START_STICKY`),
заново получает snapshot после пересоздания/подключения и работает для всех ID. Удаление одного
ID убирает только его кадр. Удаление последнего в widget-режиме освобождает этот сервис.
Обновление APK, загрузка после unlock и системные обновления AppWidget восстанавливают его.
При размещённом AppWidget автозапуск не зависит от переключателя автозапуска оверлея,
его сохранённого состояния «Запущен/Остановлен» и разрешений оверлея. Открывать MainActivity
после загрузки не требуется. До разблокировки пользователя запуск отложен; без размещённых
экземпляров сервис не запускается. QUICKBOOT_POWERON также обрабатывается после unlock.
Ранний сигнал загрузки и обновление APK дополнительно ставят одну задачу JobScheduler:
минимальная задержка 10 секунд, deadline 60 секунд; выполнение недоступно до разблокировки
пользователя и зависит от системного планировщика. Задача переживает
завершение процесса получателя; повторные сигналы заменяют ту же задачу. Перед запуском
проверяются текущий режим, наличие экземпляров и уже работающий сервис. Постоянного
опроса или принудительного выбора Online нет: источник по умолчанию применяет Media Bridge
по сохранённой настройке пользователя. `USER_UNLOCKED` в manifest сам по себе не является
путём восстановления: Android доставляет этот сигнал только динамическим получателям
([контракт Intent](https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/content/Intent.java)).
Ограничения питания конкретной OneOS прошивки требуют проверки на ГУ.

Состав RemoteViews совместим с Android 11: FrameLayout, ImageView и TextView. Основная карточка
отрисовывается существующим MediaCardView в bitmap с длинной стороной не более 800 px
(до 2.56 MB в квадратном случае); прогресс — отдельная небольшая полоса. Это сохраняет
градиенты, обложку, векторные значки, текст, отступы и скругление без нового UI-движка.
Размер/позиция областей кликов учитывают translation кнопок. PendingIntent неизменяемы,
различаются по ID и действию и направляются только явному компоненту приложения.

Полная карточка обновляется при изменении медиа, обложки, настроек или размера. Прогресс
обновляется через `partiallyUpdateAppWidget` раз в 5 секунд, без передачи всей обложки.
В этот же цикл выполняется сверка snapshot; при выключенном экране цикл не рисует и не
запрашивает данные, wake lock не используется. Периодическое обновление провайдера раз в
30 минут — дополнительное восстановление, а не таймер воспроизведения.

Transport-команды проверяются по свежему snapshot и capability mask и проходят через прежний
маршрут OverlayService. Ответ `OK` не переключает play/pause оптимистично. После обрыва
соединения карточка показывает «Нет соединения»; если подключение молчит более 20 секунд,
старый snapshot тоже перестаёт отображаться как актуальный. Сверка выполняется с шагом 5 секунд.
Новый трек очищает предыдущую обложку, а token загрузчика исключает запоздалый результат.

Жестов и draggable SeekBar в RemoteViews нет. Нажатие на источник показывает выбор прямо в
AppWidget; доступные пункты переключаются через OverlayService и Media Bridge без открытия
Activity. Избранное открывает тот же MediaCardView в диалоге MainActivity; нажатие на прогресс
открывает его для точной перемотки. Это не второй редактор настроек. Нажатие на свободную область
открывает текущий медиаисточник. Неподдержанные
команды затемнены; возможности радио/BT/USB/CPAA определяются реальным Media Bridge.

## Контракт для AtlasLauncher на Android 11

`widgetFeatures="reconfigurable|configuration_optional"` не создаёт кнопку повторной настройки
на Android 11 сам по себе. HOME должен показать «Настроить» в режиме редактирования только
при `AppWidgetProviderInfo.configure != null` и запустить объявленную Activity с существующим
`EXTRA_APPWIDGET_ID`. Для повторной настройки необходим отдельный request code: ни OK, ни
CANCELED не должны вызывать завершение/отмену первичного добавления или deleteAppWidgetId.

После `PACKAGE_REPLACED` HOME должен перечитать AppWidgetProviderInfo и пересоздать host view
с актуальными ресурсами пакета. На установленном при проверке AtlasLauncher обнаружен старый
`ApplicationInfo.sourceDir`: после install -r HOME пытался открыть уже удалённый base.apk и
показывал `Couldn't add widget`. Пересоздание HOME восстановило карточку с тем же ID и размером.
Это ограничение хоста; код AtlasLauncher в этой задаче не изменялся.

Платформенные контракты: [конфигурация](https://developer.android.com/develop/ui/views/appwidgets/configuration),
[обновления RemoteViews](https://developer.android.com/develop/ui/views/appwidgets/advanced),
[AppWidgetManager и лимит bitmap](https://developer.android.com/reference/android/appwidget/AppWidgetManager).

Результаты конкретного прогона, отдельно от возможностей платформы:
[проверка реализации](android-appwidget-verification.md).

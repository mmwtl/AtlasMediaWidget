# Проверка единых настроек — 2026-09-13

Проверена реализация из `4d1f633`, включая IPC-клиент/сервис, импорт/экспорт,
журнал восстановления и структуру экрана настроек. Это проверка данной реализации,
а не всего OEM-медиастека. Утверждение исходного плана «полностью реализовано и
верифицировано» не подтверждалось запуском и проверками смерти процессов.

## Подтверждённые дефекты

- Старый статусный TextView после переделки UI не создавался: Activity падала в onResume.
- Новые ответы IPC не содержали protocolVersion: клиент отключался с версией -1.
  Эти два дефекта исправлены отдельными коммитами до этой проверки.
- При недоступном backend экспорт сохранял только Widget, а импорт мог пропустить
  media и сообщить об успехе. Теперь операция требует backend для медиачасти.
- Запросы настроек молча терялись при отключении, не имели таймаутов и оставались
  в памяти после stop. Добавлены ошибки, ограниченное ожидание и завершение callbacks.
- Файловые дескрипторы экспорта/импорта оставались открыты после передачи Binder.
- Runtime импорт применял настройки до проверки обложек и замены каталога.
  Повреждённый архив мог частично изменить настройки.
- Проверки архивов не отклоняли повторные пути, отсутствующие файлы из hashes,
  неверные типы/диапазоны медианастроек и будущую схему media.json.
- Журнал Widget и runtime использовали разные operationId; подготовленные операции
  runtime существовали только в RAM. Потеря ответа commit приводила к безусловному
  откату Widget даже при уже применённой медиачасти.
- Файловые операции settings IPC выполнялись на main thread сервиса.
- Быстрая запись нескольких UI-настроек использовала одну старую revision.
  Во время записи UI теперь ожидает подтверждённый snapshot; sliders сохраняются
  после завершения перетаскивания. Watchdog доступен при включённой трансляции обложек.
- Сброс пользовательского каталога не требовал подтверждения удаления.

## Сборки и порядок UI

Widget сохраняет единственную distribution flavor `integrated` и приватный процесс
`:media`. Flavor `plain` и неиспользуемый установщик отдельного APK удалены.
Standalone `:api-app` сохранён для диагностики и переноса прежних медианастроек.
Package, базовая версия и имя release APK сохранены.

Порядок: разрешения → запуск/автозапуск → медианастройки → размер/положение карточки
→ текст/отступы/кнопки → поведение радио/сетка избранного → резервная копия
→ диагностика → масштаб интерфейса. Предпросмотр остаётся закреплённым над списком.

## Оставшиеся пробелы исходного плана

В Widget нет отдельного импорта старого ZIP-каталога (`stations.csv` + `covers/`)
и выбора preferred Online-проигрывателя. Полная медиакопия переносит эти данные,
но это не заменяет отдельные пользовательские операции. Этот аудит не вводит
новые IPC-команды для данных функций. Предварительный просмотр импорта также не
фиксирует revision бэкенда: подтверждение означает замену текущих переносимых
настроек содержимым копии.

## Границы доказательств

Robolectric проверяет ошибки архивов, восстановление файлов журнала, повторное
создание runtime-контроллера и callbacks. Это не эквивалент реального отключения
питания или Android process death. Проверка эмулятора не доказывает корректность
OEM Binder, выбора радио/BT/USB/CarPlay, приборки или sleep/wake на головном устройстве.

## Выполненные проверки

- `sh gradlew --offline clean check assembleRelease`: успешно.
- Widget и standalone API: package/version/APK naming и подписи `apksigner verify`.
- Manifest: один Widget launcher, приватный Bridge и diagnostics в `:media`,
  notification listener и Widget FileProvider; без install permission и plain APK.
- Android 11, 1440×1920: холодный запуск, возврат из фона, разрешения первыми,
  масштаб последним; запись USB-настройки, сохранение после возврата и восстановление
  исходного значения.
- Экспорт ZIP через Downloads: widget/media присутствуют, SHA-256 совпадают.
  Обратный импорт через системный picker, preview/confirm и холодный перезапуск
  завершились без ошибки и без незавершённого журнала.
- Runtime/controller recreation и COMMITTING replay проверены Robolectric;
  принудительная смерть процессов непосредственно во время commit и реальное
  отключение питания не проверялись.
